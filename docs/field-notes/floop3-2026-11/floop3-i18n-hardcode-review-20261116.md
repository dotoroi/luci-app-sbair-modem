# Floop3 언어팩·하드코딩 재점검 — 2026-11-16

## 결과

KO/JA PO 카탈로그는 현재 UI 문자열과 정적 검사상 일치한다. 사용자에게 보이는 페이지 표제 세 곳이 gettext를 거치지 않는 것을 추가로 발견해 수정했다.

- `signal.js`: 섹션 표제 `IMS` → `_('IMS')`
- `sim.js`: 섹션 표제 `eUICC` → `_('eUICC')`
- `sim.js`: 두 곳의 `APN` 섹션 표제 → `_('APN')`

IMS와 eUICC는 기술 약어이므로 화면에서 원문을 유지하되 이제 언어 카탈로그 조회를 거친다. APN은 기존 카탈로그의 승인된 기술어 예외를 이용한다.

## 검사 근거

- 실행: `python tools/check-translations.py`
- 결과: PASS. KO/JA 각각 975개 message ID, 39개 승인된 원문 유지 기술어, 936개 번역 문자열.
- JS/menu 정적 gettext ID 834개, Go 상태·오류 메시지 ID 129개. 빈 번역, fuzzy, 키 누락, 여분 키, 포맷 토큰/문자열 결합 공백 오류가 없었다.
- 보고서에 기록된 하드코딩 UI 후보 62개를 현재 파일 위치에서 다시 대조했다. 56개는 gettext로 감싸져 있고, 나머지 6개는 명령/프로토콜 등 그대로 보여야 하는 값이다. 이 감사 목록에서 누락됐던 IMS/eUICC/APN 세 곳은 이번에 별도로 수정했다.
- KO/JA PO를 수정했고 동봉 Python LMO 컴파일러로 두 카탈로그를 갱신했다. 두 LMO는 각각 936개 번역 항목을 포함한다. IMS/eUICC/APN의 원문 유지 항목은 LuCI gettext의 기본 msgid 표시 경로를 사용한다.

## 범위와 제한

- 실제 기기의 LuCI에서 한국어/일본어를 선택해 각 페이지를 화면으로 확인하지 않았다.
- 셸 기반 `check-i18n.sh`의 GNU gettext 교차 검사는 Windows 환경에 `sh`가 없어 실행하지 않았다. Python 정적 검사는 통과했다.
- Go 실행 파일은 재빌드하지 않았다. 설치 시 재빌드하기로 한 계획에 따른다.
- Wi-Fi 프로토콜 이름, WPA 모드, 인터페이스/경로, SIM 식별 규격, modem 명령 및 수치는 기능상 값 또는 기술 식별자로 분류했다. 자연어 UI 문구는 카탈로그 검증 대상에 포함했다.
