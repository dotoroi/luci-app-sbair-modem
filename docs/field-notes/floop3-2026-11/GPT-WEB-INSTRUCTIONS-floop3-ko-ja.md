# GPT 웹 작업 지침: Floop3 한국어·일본어 언어팩 완성

이 ZIP에는 Floop3 LuCI 앱의 영어 기준 PO, 한국어·일본어 PO, gettext 미번역 문자열 목록, 하드코딩 UI 문자열 목록, 관련 JS/Go 소스, 메뉴 JSON, i18n 검사·빌드 도구가 들어 있다.

## 요청 작업

1. `po/ko/luci-app-sbair-modem.po`와 `po/ja/luci-app-sbair-modem.po`를 검토해 영어 원문이 그대로 남은 사용자 표시 문구를 모두 자연스러운 한국어·일본어로 번역한다. CSV는 위치 안내와 누락 현황 참고용이며, 완료 여부는 실제 PO 전체를 기준으로 판단한다.
2. `msgid`는 변경하지 않는다. AT 명령, 네트워크 인터페이스명, 파일 경로, 프로토콜·표준 약어와 코드 식별자는 필요한 경우 원문을 유지하고 기술용어 허용 목록에 기록한다.
3. `%s`, `%d`, `{name}` 등 포맷 인자, 이스케이프, 개행, 문자열 조각 결합, HTML/JS 코드 의미를 보존한다. 번역된 `msgstr`가 코드 포맷 검증을 통과하도록 한다.
4. `floop3-hardcoded-ui-literals.csv`와 JS 소스를 보고 gettext를 거치지 않는 사용자 표시 문구를 식별한다. 실제 사용자 라벨·헤더·상태 텍스트를 `_('...')`로 연결하고 KO/JA 카탈로그에도 번역을 추가한다. 명령 예시, 경로, 상태 데이터 토큰은 무조건 번역하지 말고 문맥에 따라 구분한다.
5. `tools/check-i18n.sh`의 미번역 검증을 개선한다. `msgstr`가 비어 있는 항목뿐 아니라 `msgstr == msgid` 잔존도 찾아야 한다. 영어로 유지할 고유 기술어는 제한적인 명시적 허용 목록으로 관리하고, 긴 설명·경고문은 예외 처리하지 않는다.
6. 메뉴 제목과 Go 백엔드에서 만들어지는 사용자용 오류·상태 문자열도 포함해 세 언어(영어 기준, 일본어, 한국어)의 카탈로그 키 정합성을 검증한다. 특히 일본어·한국어의 카탈로그를 각각 독립적으로 검사한다.
7. 결과물로 수정된 KO/JA PO 파일, 코드와 검사 스크립트 diff, 번역 유지 허용 목록, 빌드·검증 결과를 제시한다. 실제 장비 설치나 설정 변경은 하지 않는다.

## 현황 근거

- 정적 JS gettext 키 772개 중 한국어는 681개, 일본어는 684개가 영어 원문과 동일했다. 양 언어 모두 키 누락은 없었지만, 동일한 영어 `msgstr`는 `msgattrib --untranslated` 검사에 걸리지 않았다.
- 영어 원문 그대로인 긴 설명·경고 문자열은 각 언어에서 166개로 확인됐다.
- 설치된 Floop3 KO/JA `.lmo`와 로컬 생성 파일 해시가 일치했고 장비 언어는 `ko`였다. 따라서 남은 주 문제는 카탈로그 번역률과 gettext를 우회하는 코드 문자열이다.
- 원문 목록은 `reports/floop3-ko-untranslated-strings.csv`; 하드코딩 후보는 `reports/floop3-hardcoded-ui-literals.csv`에 있다.
