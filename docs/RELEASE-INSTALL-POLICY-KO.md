# Floop3 릴리스 설치 정책

대상은 제조사 OpenWrt 21.02.7이 설치된 SoftBank Air Terminal 6(SBA6D)이다. 각 릴리스에 설치 가능 조건, 펌웨어별 실기 검증 결과, 업그레이드 지원 범위를 함께 표기한다.

## 설치 경로 선택

| 장치 상태 | 설치 정책 |
|---|---|
| 순정 SBA6D, LuCI 없음 | 같은 버전 문서의 [LuCI bootstrap](../extras/luci-bootstrap/README.ko.md) 사전 점검을 통과하면 bootstrap부터 적용한다. TCP/8080에서 LuCI 로그인과 기존 TCP/80 순정 UI를 확인한 뒤 Floop3를 별도로 설치한다. |
| 순정 SBA6D, LuCI 있음, Floop3 없음 | 사전 검사와 백업 후 ARM64 릴리스 번들로 신규 설치한다. 현재 LuCI 주소와 포트를 사용한다. |
| 기존 Floop3 또는 같은 경로를 사용하는 다른 구현이 있음 | 기존 파일의 출처와 해시를 확인한다. 릴리스가 명시적으로 지원하고 검증한 이전 버전에서만 업그레이드한다. 소유권을 확인하지 못하면 기존 파일을 보존하고 설치를 중단한다. |
| 다른 모델, OpenWrt 타깃, 미확인 KNOS 버전 | 해당 조합을 검증해 지원 목록에 추가할 때까지 설치를 보류한다. |

## 사전 검사와 복구 준비

1. 장치 모델과 아키텍처, KNOS 버전, OpenWrt revision·target, 활성 슬롯, 현재 LAN 주소를 기록한다. v0.1.0 설치기의 KNOS 허용 목록은 0.09.45, 1.00.22, 1.01.20, 1.01.44, 1.01.52다. 각 버전의 실기 합격 여부는 릴리스 노트에서 따로 확인한다.
2. 기존 관리자 SSH 키로 새 세션을 열고 LuCI 접속을 확인한다. 설치 중 LAN 관리 경로가 끊길 때 사용할 독립 복구 경로도 확인한다.
3. PC에 설정과 설치 대상 파일을 보관한다. 특히 방화벽·네트워크 설정과 기존 앱 서비스·부팅 링크, 번역 파일, `/etc/sbair`의 존재 여부와 사본을 기록한다. 롤백 때 이전 파일은 백업에서 복원하고, 이번에 새로 생긴 항목만 제거한다.
4. 릴리스 버전을 고정해 내려받고 PC에서 아카이브 체크섬, 장치에서 내부 체크섬을 확인한다. 실제 아카이브와 설치 크기로 공간을 계산한다. v0.1.0 기준은 `/tmp` 20 MiB, `/overlay` 24 MiB이며 장치에 남기는 백업 공간은 별도다.
5. 방화벽 등에 미적용 UCI 변경이 있으면 먼저 검토해 정리한다. 현재 설치기는 방화벽 설정을 커밋하므로 보류 중이던 설정도 함께 저장될 수 있다.

## 실기 합격 기준

- **설치 직후:** 새 SSH 세션, 기존 순정 UI, 기존 LuCI 로그인, Floop3 메뉴를 확인한다. `ubus call sbair overview`의 유효한 응답까지 확인한다.
- **기능:** 모뎀 상태 조회, Wi-Fi 대역·MLO 상태, LAN 주소와 DHCP, 배포 대상 언어의 Floop3 화면을 확인한다. SIM 망 등록 성공 여부는 상태 조회와 별도로 기록한다.
- **재부팅:** 시험 장치에서 최소 120초간 부팅을 관찰하고 SSH·LuCI·RPC 및 서비스 자동 시작을 다시 확인한다.
- **롤백:** 시험 장치에서 이전 설정과 앱 파일을 복원한 후 새 SSH, LuCI와 LAN 동작을 확인한다. 설치·업그레이드·복구 결과는 각각 기록한다.

## 다음 릴리스의 배포 기준

1. 버전이 고정된 ARM64 설치 번들, SHA-256, 소스 커밋이 포함된 빌드 정보, 설치·제거 안내를 함께 제공한다.
2. Floop3 전용 한국어·일본어 카탈로그를 번들에 포함하고, LuCI 기본 언어팩의 준비 방법을 별도로 안내한다. 빈 설치 환경에서 언어 선택과 전용 메뉴 번역을 확인한다.
3. 기존 설치를 업그레이드 대상으로 지원하려면 기존 `sbair-netmode`의 출처와 동작을 확인하고, 현재 네트워크 설정 보존 및 롤백을 검증한다. 확인되지 않은 해시의 허용 목록 추가로 이 검증을 대신하지 않는다.
4. 1.01.20에서 신규 설치·재부팅·복구를 우선 검증한다. 0.09.45, 1.00.22, 1.01.44, 1.01.52는 각각 실기 결과를 얻은 뒤 지원 범위를 넓힌다. 1.01.52에서는 WAPP·hostapd와 실제 AP 접속도 확인한다.
5. 필수 검증이 남은 버전은 시험 배포로 표시한다. v0.1.0은 공개 번들을 실기 임시 루트에 설치하는 데 성공했으며, 현재 1.01.20 기기의 기존 구현을 사용한 업그레이드 시험에서는 소유권 검사에서 중단됐다. 앱 전용 KO·JA 파일과 제거 스크립트도 빠져 있다.
